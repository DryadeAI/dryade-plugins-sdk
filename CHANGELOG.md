## [1.1.5] — 2026-05-26

Initial public release. The SDK is the pure-contract package that Dryade
plugin authors install from PyPI.

### Added

- **Protocols (core)** — `Plugin`, `Agent`, `Tool`, `Route`, `Config` with
  `@runtime_checkable` decorators so the host can structurally verify
  conformance at load time.
- **Protocols (supporting)** — `KV`, `Leash`, `IsolationLevel` for shared
  state and sandbox-policy declarations.
- **Manifest v2** — `ManifestV2` dataclass that validates against the
  bundled v2 JSON schema (`dryade-manifest-v2.schema.json`).
- **Packaging primitives** — `compute_plugin_hash_pair`, `sign_manifest`,
  `load_private_key`, `verify_plugin_hash`, `CONTRACT_VERSION` constant
  (set to 4 — SHA-256 + SHA3-256 dual hash).
- **Hook decorators** — `@traced`, `@hook` as no-op shims the host wraps
  with observability at load time.
- **Exception hierarchy** — `DryadePluginError`, `PluginValidationError`,
  `ManifestValidationError`, `AgentExecutionError`, `HashMismatchError`.
- **Testing subpackage** — `dryade_plugins_sdk.testing` ships `FakeHost`,
  `FakeRegistry`, `MockKV`, `MockConfig`, `MockLLM`, `LLMCall` and the
  `build_plugin` / `build_agent` / `build_tool` factories so authors can
  pytest their plugins without installing the host runtime.
- **Decorators** — `@tool(name=..., description=...)`,
  `@route(path=..., method=...)`, `@agent(...)` for ergonomic scaffolding.
- **Route wiring** — `collect_routes(plugin)` and `build_router(plugin)`
  walk a plugin instance and produce a FastAPI `APIRouter` from every
  `@route`-decorated method (lazy-imports FastAPI; a pre-built `self.router`
  is returned unchanged).
- **SBOM** — `dryade plugin package` embeds a CycloneDX SBOM as
  `sbom.cdx.json` in every `.dryadepkg` (full SBOM via `cyclonedx-py` when
  available, minimal shim otherwise; the manifest records the source).
- **Documentation site** — `sdk.dryade.ai` with Getting Started, Concepts,
  API Reference, CLI Reference, Cookbook, Examples, FAQ, Migration,
  Security, Changelog pages.
- **Examples** — five reference plugins (`hello_world`, `with_tool`,
  `with_llm`, `with_ui`, `multi_agent`) under `examples/`.
- **CI workflows** — full matrix on Python 3.11 / 3.12 / 3.13 + defense-in-depth
  (zero host-runtime imports gate, hash-conformance gate,
  community-tier rejection gate), hermetic E2E smoke,
  OIDC trusted publishing to PyPI, OpenSSF Scorecard, CodeQL Python
  analysis, dependency-review on PRs, dependency-review-action.
- **Community files** — `CONTRIBUTING.md`, `CODE_OF_CONDUCT.md`,
  `SECURITY.md`, issue templates (bug / feature / question / config),
  PR template, `.all-contributorsrc`, `FUNDING.yml`, labeler workflow,
  welcome workflow, release-drafter workflow, all-contributors workflow.

### Security

- Plugins ship with author Ed25519 dev keys generated by
  `dryade plugin keygen`. Key permissions are enforced to `0o600` at
  generation time.
- `.dryadepkg` is a gzipped tar archive containing a v2 manifest with
  `plugin_hash_sha256` + `plugin_hash_sha3_256` + 128-char hex Ed25519
  signature. The signature is computed over the **final** manifest (hashes,
  contract version, and SBOM source all included) and verifies against the
  author's public key. Authors never see platform signing material.
- The SDK and CLI have **zero** host-runtime imports — verified by
  `tests/test_zero_core_imports.py` running in CI on every PR.
- `tests/test_no_internal_leaks.py` scans every author-visible file and runs
  as a required CI job, so the published package documents only the public
  author contract.
- `--tier community` is rejected at validate, scaffold, and package time
  (`community` is not a valid plugin tier).

### Notes

- Test suite: unit, defense-in-depth, examples, packaging-signature, and
  hermetic E2E smoke all run green on Python 3.11 / 3.12 / 3.13.
- Contract version pinned to **4**. Plugin authors should pin
  `dryade-plugins-sdk>=1.0.0,<2.0.0` to stay on this contract.
